# Nordic Desk engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested Python engine that keeps a local Yahoo price store, reads the real holdings and the Nordnet record, computes every number on the Aamu and Huurre mockups, and writes them as JSON for the front end.

**Architecture:** Package `nordic_desk` under `src/`. Small modules per job: config, price store, euro panel, stock metrics, portfolio risk, Nordnet import, build CLI. Pure functions take pandas objects so tests need no network; only `prices.update` touches Yahoo. The front end is a second plan and only reads `out/*.json`.

**Tech Stack:** Python 3.12, uv, pandas, numpy, yfinance, pypdf, pytest. TOML read with `tomllib`.

**Spec:** `docs/superpowers/specs/2026-11-18-nordic-desk-design.md`. Reference code for every formula: `docs/mockups/src/gen.py` (stock metrics), `docs/mockups/src/analysis.py` (portfolio risk, scenarios, record).

## Global Constraints

- `uv` only (`uv sync`, `uv run`); never install into global Python.
- Git-ignored: `data/`, `out/`, `config/*.local.toml`, `*.csv` exports. Real holdings, export files and the account number are never committed; tests use invented holdings.
- Default history start `2015-01-01`. Window for risk: last 252 daily returns ending at the last full US close.
- Trading-day offsets: 1 week 5, 1 month 21, 3 months 63, 6 months 126; YTD from the last close before 1 January; volatility ×√252, short volatility over 21 returns.
- Bad-day threshold: portfolio return ≤ 20th percentile. Effective holdings include cash.
- Euro conversion: USD price ÷ `EURUSD=X`, carried forward.
- Commit messages: Conventional Commits; end with the attribution line the session gives.

## Review Focus

- A ticker Yahoo returns empty for (delisted or mistyped) → `update` reports it by name and the build continues without it.
- A holding with no instrument mapping → import lists it as unmapped and keeps its value as zero-return, never drops the money silently.
- Nordnet numbers with thin spaces, comma decimals and `−` minus (e.g. `−152,47`, `10 345,67`) → parsed exactly.
- A holiday where one market is closed → forward-fill, no NaN reaches the covariance.
- Running build twice in a day → `update` fetches only the missing tail, the store has no duplicate dates.
